# AVX-vectorized GEMM — деductive verification (Frama-C/WP + Coq)

Верификация умножения матриц `C = A * B`, реализованного через AVX-интринсики
(`_mm256_setzero_ps`, `_mm256_set1_ps`, `_mm256_loadu_ps`, `_mm256_storeu_ps`,
`_mm256_fmadd_ps`), средствами Frama-C/WP с ACSL-спецификациями, часть целей
добивается интерактивно в Coq.

## Файлы

- `gemmv2.c` — сама функция `gemm_v2` с полной ACSL-спецификацией:
  индуктивная аксиоматика `DotProduction`/`RowResult`/`MatrixResult`/`zeroed`
  (та же теория, что и в невекторизованной версии проекта), инварианты циклов,
  промежуточные `assert`-подсказки для решателя.
- `immintrin.h` — аксиоматизированная модель AVX-интринсиков. Реальные
  инструкции не разбираются инструментом — вместо этого функции объявлены
  без тела, с ACSL-контрактом (`requires`/`ensures`), который принимается
  на веру для вызывающего кода. Это и есть граница доверия (TCB) этого проекта.

## Модель AVX-регистров: `REG` + `COUNTER`

Регистр `__m256` моделируется как `float*`. Поскольку реальный адрес
регистра для инструмента не имеет значения (лишь бы разные регистры не
пересекались друг с другом и с реальными массивами `A`/`B`/`C`), используется
приём "growing arena": глобальный `REG` + счётчик `COUNTER`, где каждый вызов
интринсика, возвращающего регистр, "выделяет" свежий слот
`REG[8*COUNTER .. 8*COUNTER+7]` и увеличивает `COUNTER` на 1.

Ключевые моменты дизайна (набитые шишки, задокументированы в истории проекта):
- `\separated` между регистром-аргументом и новым слотом формулируется
  **точечно** (`REG + (8*COUNTER .. 8*COUNTER+7)`), а не как
  `\forall i>0; \separated(a, REG+(0..i))` — последнее логически противоречиво,
  если сам аргумент `a` тоже оказывается срезом `REG`.
- `\valid`/`\valid_read` на результат каждого интринсика указаны явно в
  `ensures` — это бесплатно (у функций нет тела, доказывать нечего), но
  экономит решателю обязательный шаг вывода на каждом использовании результата.
- `assigns REG[...]` — узкий (только новый слот), а не `REG[0..8*COUNTER-1]`.

## Статус доказательства

На момент последнего прогона (`frama-c -wp -wp-rte`):

```
Proved goals:   85 / 182
  Qed:            84
  Alt-Ergo:        1
  Failed:         96
  Timeout:         1
```

Оставшиеся цели укладываются в понятные категории (см. историю работы):
границы строк матриц (`math_bounds` + инстанциация), отделённость регистра
от места записи (`separated_trans`), собственно `DotProduction`-шаги
(`step0`..`step15`), и производные от них (`dot_done`/`row_done`/`mat_step`,
инварианты циклов). Часть из них уже добита вручную в Coq — см.
рабочие `.v`-файлы (не в этом репозитории, в соседней рабочей директории).

## Как прогнать

```bash
frama-c -wp -wp-rte -wp-timeout 10 gemmv2.c
```
